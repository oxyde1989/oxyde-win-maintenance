## _1 — 2026-10-18 09:31 — Repository analysis and direction

**Status:** direction accepted, implementation pending.
**Scope of this note:** assessment of the current repository and the proposed
evolution into a simple, fast PC health-check tool, derived from the real
maintenance session performed on this machine (2026-10-17/18).

### Context

`oxyde-win-maintenance` is a portable Windows toolkit (PowerShell 5.1, zero
external dependencies) made of read-only probes that produce a JSON/HTML report,
plus a guarded action layer (plan -> dry-run -> apply) and a WinForms console.
Architecture: `probes\NN-Area.ps1`, `actions\NN-kind.ps1`, `lib\Common.psm1`,
`render\Report-Html.ps1`, `out\` for artifacts. Report schema v4, decisions
logged ADR-style (D1–D12).

The real maintenance session on this PC found: **2101 component-store
corruptions** repaired by DISM (401 CSI payload + 1700 CSI file flags), repeated
**ungraceful shutdowns** (Kernel-Power 41 / EventLog 6008) as the likely cause,
a **Windows Update stall since August 2026**, ~32 GB of recoverable disk space
(`CrossDevice`, WinSxS, npm cache, Temp, shadow storage), a **disabled Defender**
plus third-party AV residue (Avira, Malwarebytes, PRI-Driver, MBAM), a leftover
LibreOffice service, a missing x86 .NET runtime breaking Intel DSA, and pending
reboot residue (`PendingFileRenameOperations`).

### Verdict

Strong foundations (plugin architecture, safety by design, ADR discipline), but
today it is a **maintenance scanner for technicians**, not yet a "simple and
fast health check". It would not have found the headline problems of the real
session, and the UX does not end in a single verdict.

### Strengths

- **True portability:** PowerShell 5.1, no install, copy the folder and run (D2).
- **Safety by design:** read-only probes (D3); catalog-only actions; dry-run by
  default; per-action confirmation; a single UAC per batch (D7/D8); transcript;
  undo artifacts; **post-apply re-scan + before/after diff**.
- **Clean contracts:** `New-Finding` / `Write-ProbeResult` / `New-ActionResult`;
  plugin discovery by filename; adding an area is one file.
- **Serious report:** schema v4, dark/light, filters/search, DataTables, KPIs,
  tooltips, sidebar navigation.
- **Rare discipline:** DECISIONS/ROADMAP kept in sync; D6 (no machine-specific
  knowledge) is the right call for reuse; D12 avoids phantom driver false
  positives.

### Weaknesses

#### Product & UX

- No **health verdict** or score: the Findings tab is a raw grid; a non-expert
  cannot answer "am I healthy? what should I do?".
- No **scan profiles**: always "everything" (27.6 s on this host, dominated by
  Windows Update 10.5 s, winget 5 s, drivers 3.5 s). No quick (<10 s) and no
  deep on demand.
- **Report is CDN-only** (D5): unstyled without internet — a conflict with use
  on other PCs.
- GUI is a **thin shell**: no "Run health check" primary action with a verdict.

#### Diagnostic coverage gap

What the real maintenance found vs. what the tool checks today:

| Real issue from the maintenance session | Covered now? |
|---|---|
| 2101 component-store corruptions (DISM/SFC) | No |
| Ungraceful shutdowns (Kernel-Power 41 / 6008) as root-cause hint | No |
| Space: CrossDevice ~18.7 GB, WinSxS, Temp, npm, shadow storage (4.43 GB limit) | No (only free %) |

#### Technical / quality

- **winget parsing is fragile:** the latest scan (2026-10-18 09:17) returned
  *"Unparseable winget output"* classified as `INFO`, which would **hide** a real
  problem from any verdict.
- Probes run **sequentially**; a single 300 s global timeout (no per-probe
  declared timeout).
- `New-Finding` has no `severity`/`weight`/`category` -> no scoring possible.
- Documentation drift: the `PcScan.ps1` synopsis/`-Areas` comment does not list
  the `Drivers` area.
- **No tests/CI:** trust on other PCs would benefit from at least a smoke test.
- **Repo lives inside OneDrive:** `.git` and `out\` are synced, risking bloat and
  conflicts.
- **Uncommitted work:** `probes\30-Drivers.ps1` and
  `actions\20-winget-upgrade.ps1` untracked; `PcApply`/`PcConsole`/`PcPlan`,
  docs and renderer modified (D11/D12 not committed).

### Confirmed decisions (2026-10-18)

- **Perimeter:** diagnosis with a verdict + safe guided fixes (remediation for
  low-risk cases only, behind the existing guardrails).
- **Offline:** vendor the report assets locally so styling works without the
  internet; features that inherently need the network (winget, Windows Update,
  app/driver updates) are explicitly labelled "requires network".
- **Default profile:** `quick`, target < 10 s.
- **Deep scan:** optional and separate, requires admin, one UAC prompt; declared
  in the report.
- **Repo location:** move out of OneDrive — **deferred**.

### Plan

#### P0 — Make it "simple and fast"

1. **Scan profiles** (new `lib\Profiles.psm1` or `profiles.psd1`, declarative):
   `quick` (default) / `standard` / `deep`.
   - `quick` = host, space, `PendingReboot`, lightweight WU (last hotfix +
     service state, no COM search), Defender/signatures, orphan services, fast
     critical-event checks. Target < 10 s.
   - `standard` = as today (WU COM, winget, drivers).
   - `deep` = integrity (DISM `/ScanHealth`, `sfc /verifyonly`), SMART,
     BitLocker/TPM, full event log; elevated, one UAC, declared in the report.
   - `PcScan.ps1`: add `-Profile`, per-probe timeout map, profile-based area
     selection.
2. **Health verdict:** extend `New-Finding` with `category`/`weight`; report
   schema **v5** (back-compatible) adds
   `health: { score, verdict: OK|WARNING|CRITICAL, topIssues[], profile, adminUsed }`;
   **exit code** 0/1/2 for scripting.
3. **Offline report:** vendor Bootstrap, Bootstrap Icons, DataTables, Chart.js
   and the Inter font (woff2) under `assets\`; minimal inline fallback when the
   assets are missing; hero verdict banner + score.
4. **winget fix** (`probes\21-Winget.ps1`): parser hardening; unparseable output
   becomes `WARN`/`CRIT` with evidence (never a silent `INFO`); label "requires
   network".
5. **GUI:** primary **"Run health check"** button with a verdict banner and
   "issues only"; a separate "Deep scan (admin)" action.
6. **Hygiene:** commit the pending work; align `PcScan` synopsis/GUIDE (Drivers
   area); `out\` retention; `-Version`.

**Acceptance P0:** `.\PcScan.ps1 -Profile quick -Open` yields a verdict + score
in < 10 s, the report is readable offline, and the exit code reflects the
verdict.

#### P2 — Targeted remediation + packaging

- Actions: `30-wu-install` (per-update, drivers with video excluded from the
  bulk), `40-app-uninstall` (MSI/Quiet/AppX), `50-service-delete` (residue, with
  `.reg` undo), `60-integrity-repair` (DISM+SFC, elevated, explicit),
  `70-hibernation`, `80-clean-caches` (estimate + undo), `90-defender`.
- Packaging: `Run-HealthCheck.cmd` + zip release; scheduled scan with **trend**;
  baseline for cross-PC comparison.
- Tests: smoke test + fixtures; CI.

### Notes and risks

- Profiles are not absolute truth: `INFO`/`unknown` (e.g. missing elevation) must
  never count as "healthy" in the verdict.
- Network-dependent actions must expose a "requires network" state, not fail
  silently.
- The OneDrive repo location remains a performance/sync liability while the move
  is deferred.

### Deferred

- Move the repository out of OneDrive (to e.g. `D:\ProgettiMiei\`).
- Vendor-vs-CDN policy revisited once the offline report lands (D5 update).
