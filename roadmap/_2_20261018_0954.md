### 4. Residual issues (new, for the implementation role)

**R1 — medium — a quick scan can report "healthy" on incomplete coverage.**
Pending updates are not checked in `quick` and that is only `INFO`
(`wu-summary`, "Pending updates: not checked (quick profile)"). The verdict
ignores it, so a machine whose Windows Update has been stalled for months — the
real situation on this host before the maintenance — would still come out `OK`.
This contradicts the `_1` risk note ("unknown must never count as healthy").
*Recommendation:* add `health.coverage` (`areasRun`, `areasSkipped`,
`networkDependent`, `elevated`) and render the verdict as "OK (partial)" (or
demote) when high-signal checks were skipped.

**R2 — medium — the score double-counts item + summary findings.**
Quick `84` = 100 − 8 × 2, but both WARNs describe the **same single** issue
(`Orphan service: LibreOfficeMaintenance` + its summary). Standard `60` = −8 × 5
for 3 real issues. *Recommendation:* tag summary findings (e.g.
`category = 'summary'`) and exclude them from scoring; expected scores on this
host become 92 (quick) and 76 (standard).

**R3 — low/medium — `-Profile deep` from the CLI neither elevates nor warns.**
The engine has no elevation check: the report states `profile = deep` with
`adminUsed = false`, which is misleading. Only the GUI elevates.
*Recommendation:* print an explicit warning and add an INFO finding "deep profile
requested without elevation", or self-relaunch once with `-Verb RunAs` (same
pattern as `PcApply`).

**R4 — low — documentation style drift.** `DECISIONS` D13 heading uses `-`
while D1–D12 use `—`.

**R5 — medium (scope, not defect) — `quick` is still thin.** It runs
WindowsUpdate (light), PendingReboot and OrphanServices only. The `quick` content
specified in `_1` (space consumers, Defender/signatures, fast critical events)
does not exist yet because the probes are P1. This is the main driver for the
next batch.

Accepted, no action: `assets\vendor\inter\inter.css` declares five weights from a
single variable `Inter.woff2` — valid and verified.

### 5. P1 plan — "make `quick` a real health check"

Objective: the default health check must show the picture that actually mattered
in the real maintenance session (unexpected shutdowns, component-store integrity,
disk space, Defender state).

**Batch 1 — new probes + three engine fixes**

| New probe | Scope | Profile | Cost target |
|---|---|---|---|
| `06-EventLog.ps1` | Kernel-Power 41, EventLog 6008, BugCheck 1001, top recurring errors (30/90 days) | quick | < 1.5 s |
| `70-Space.ps1` | Main consumers per drive: shadow storage usage **and limit** (`vssadmin`), WinSxS, `hiberfil`, `pagefile`, Temp, WER, Recycle Bin, `Windows.old` | quick | < 2.5 s |
| `60-Security.ps1` | Defender real-time protection + signature age, third-party AV / residue providers, Firewall profiles | standard (RTP + signature age also in quick if < 0.5 s) | < 1.5 s |
| `05-Integrity.ps1` | Read-only CBS / CbsPersist tail: last `Total Detected Corruption`, `RepairNeeded`, pending servicing operations; **deep only**: `DISM /ScanHealth` + `sfc /verifyonly` (elevated) | quick (read) | < 1 s |

Engine changes required by the batch: **R1** (`health.coverage`), **R2**
(scoring excludes summary findings), **R3** (deep-without-elevation warning);
`profiles.psd1` `quick` gains EventLog, Space, Integrity-read, Security-lite;
version 0.6.0 (additive `health` fields, schema stays v5 — no reader breakage).

**Batch 2 — deep and leftovers (after Batch 1 is verified)**

`31-Storage.ps1` (SMART/reliability, deep), `80-Startup.ps1` (Run keys, Startup
folder, scheduled tasks with missing targets, standard), `90-UpdateHealth`
(wuauserv/BITS, last success, failure history, SoftwareDistribution size — folded
into `10-WindowsUpdate.ps1`), and the elevated deep runs of Integrity.

**Acceptance criteria (measurable)**

1. `PcScan.ps1 -Profile quick` wall time **< 10 s** on this host with the four
   new areas (engine and wall measured separately).
2. A quick scan on this host reports: CBS corruption history (2 101 detected, 0
   pending after the repair), unexpected shutdowns (Kernel-Power 41 count and
   last date), shadow-storage limit/usage, Defender real-time state + signature
   age, free space per drive.
3. Scoring no longer counts summary findings (quick score on this host becomes
   92 for a single orphan service).
4. `-Profile deep` unelevated prints an explicit warning and the report carries
   the notice.
5. No regressions: `PcPlan` still yields 3 actions for a 1-row winget dataset;
   `PcApply` dry-run unchanged; schema stays v5 and v4 readers keep working.
6. Every new probe is read-only (D3), needs no elevation for its quick part,
   registers datasets with renderer titles/labels, and is documented (GUIDE
   areas table, DECISIONS if a new contract is introduced, ROADMAP status).

**Out of scope for P1** — P2 actions (`wu-install`, `app-uninstall`,
`service-delete`, `integrity-repair`, `hibernation`, `clean-caches`,
`defender`), packaging (`Run-HealthCheck.cmd`, zip release), tests/CI, and the
deferred move of the repository out of OneDrive.
